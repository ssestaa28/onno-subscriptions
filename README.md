# Сервис подписок на onno

Тестовое задание: учёт клиентов, тарифов, пополнений лицевых счетов и подписок.
Решение на Java 21, Spring Boot 3.4.4 и onno 3.4.1. Модель описана аннотациями
и типизированными Java-классами; схему БД, миграции, REST API, списки, формы
и отчёты генерирует onno. Собственных CRUD-контроллеров, DTO и SQL-миграций нет.

## Запуск

Нужен JDK 21 и доступ к интернету при первой сборке. Maven, Gradle и Node.js
отдельно устанавливать не нужно: Gradle Wrapper включён, интерфейс входит
в опубликованный `onno-ui-starter`.

Windows PowerShell, из папки проекта:

```powershell
.\gradlew.bat --gradle-user-home .gradle-home bootRun
```

Linux / macOS:

```bash
chmod +x gradlew
./gradlew bootRun
```

Откройте **http://localhost:8080/ui/**. Логин `admin`, пароль `admin`.
Для ручной проверки используйте обычный браузер с шириной страницы больше
1023 CSS-пикселей (развёрнутое окно, масштаб 100%). В onno 3.4.1 есть ошибка
карточек с полями выбора при ширине 768–1023 пикселя, в том числе во встроенном
просмотре VS Code: `React.Children.only…`. Подробнее: [особенности фреймворка](docs/framework-notes.md).
Пароль для другого окружения задаётся переменной `APP_ADMIN_PASSWORD`.
Порт по умолчанию 8080; его можно изменить переменной `PORT`.

Приложение начинает с пустых справочников. Данные сохраняются в файловой H2
`data/subscriptions.mv.db` и переживают перезапуск. История автоматически
применённых изменений схемы хранится в `onno_schema_history`.

Сборка исполняемого JAR и запуск без Gradle:

```powershell
.\gradlew.bat --gradle-user-home .gradle-home bootJar
java -jar build/libs/onno-subscriptions-1.0.0.jar
```

## Как проверить приложение вручную

1. В разделе «Справочники → Клиенты» создайте клиента, укажите имя и контакты.
2. В «Тарифы» создайте два доступных тарифа: «Месяц», 100 ₽ / 30 дней,
   и «Год», 900 ₽ / 365 дней.
3. В «Документы → Платежи» создайте платёж клиента на 1500 ₽, сохраните
   и проведите его. Простое сохранение денег на счёт не добавляет.
4. В «Подписки» выберите клиента и дату начала, добавьте две строки:
   «Месяц» на 2 периода и «Год» на 1 период. Сохраните документ.
   Цена берётся из тарифов; итог 1100 ₽, дата окончания = начало + 365 дней.
   Расчётные поля доступны в сохранённом документе и списке.
5. Проведите подписку: остаток станет 400 ₽. В отчёте выручки появятся
   200 ₽ / 2 периода по месячному тарифу и 900 ₽ / 1 период по годовому.
6. Попробуйте провести ещё одну подписку дороже 400 ₽: операция отклоняется,
   остаток и выручка не меняются.
7. Через действие «Отменить подписку» в списке или карточке введите причину.
   Остаток вернётся к 1500 ₽, выручка по отменённой подписке станет нулевой.
8. Откройте «Отчёты»: доступны остатки лицевых счетов и обороты выручки
   за период по тарифам и клиентам. Дашборд показывает пополнения, выручку,
   график по дням и последние подписки.

## Бизнес-правила и принятые решения

- Платёж создаёт приход в регистр `PersonalAccounts` типа `BALANCE`.
  Сумма строго положительная, существующий клиент и способ оплаты обязательны.
- Подписка создаёт расход по лицевому счёту и приход в `TariffRevenue` типа
  `TURNOVER`: измерения — тариф и клиент, ресурсы — сумма и число периодов.
- `allowNegative = false` на регистре лицевых счетов: недостаток средств
  проверяется onno в транзакции, а не только предварительным чтением остатка.
  Отказ откатывает списание, выручку и проведение документа вместе.
  `PostingErrorAdvice` переводит этот отказ в HTTP 409 с понятным сообщением.
- Требуются существующий клиент, хотя бы одна строка, положительное целое
  число периодов в каждой строке и доступные тарифы. Проверки реализованы
  через `Validated` и `BusinessRule`; они работают при сохранении и проведении.
  Удалённые справочники не допускаются в новых документах.
- Черновик при каждом сохранении получает актуальные цену и длительность
  из тарифа. Цена × число периодов даёт сумму строки; итог — сумма строк.
  Срок в днях — максимум `длительность периода × число периодов` среди строк.
- Проведённая подписка сохраняет купленные цену и длительность. Изменение
  тарифа и фоновое обновление статуса не пересчитывают стоимость покупки.
  Для изменения финансовых условий документа необходимо снять проведение,
  изменить и сохранить документ, затем провести заново.
- Дата окончания **не включается** в срок: интервал `[начало, окончание)`.
  Например, начало 1 октября и 30 дней означают действие до 30 октября
  включительно, статус «Истекла» с 31 октября. Бизнес-часовой пояс — Москва.
- Статусы: «Черновик», «Ожидает начала», «Активна», «Истекла», «Отменена».
  При проведении статус определяется сразу. `SubscriptionStatusJob`
  (`@ScheduledJob` + `BackgroundTask`, JobRunr) каждые 5 минут обновляет статусы
  по датам; черновики не активирует, отменённые подписки не возобновляет.
  После снятия проведения при следующем запуске задания статус станет
  «Черновик». Истечение не возвращает деньги: выручка признаётся при покупке.
- Отменённая подписка не создаёт новых движений. Отмена проведённой подписки
  выполняется атомарным `repost`: прежние движения становятся неактивными,
  деньги возвращаются, выручка исключается. Неактивная история сохраняется.
  Повторная отмена не возвращает деньги второй раз. Обычное изменение поля
  статуса на «Отменена» у проведённого документа запрещено.
- Статус клиента хранится для учёта. Задание не задаёт запрета покупок
  заблокированными клиентами, поэтому дополнительного ограничения нет.
- `DomainServices` — небольшой мост к Spring-контексту: onno создаёт
  доменные объекты вне Spring, поэтому lifecycle-методам нельзя внедрить
  `RefResolver` обычным `@Autowired`. Основная логика остаётся в модели.

## Проверки

```powershell
.\gradlew.bat --gradle-user-home .gradle-home clean check bootJar
```

```bash
./gradlew clean check bootJar
```

Интеграционные тесты запускают настоящий Spring-контекст, метамодель onno,
автоматически созданную схему H2, JDBC-репозитории и механизм проведения.
Проверяются расчёты, максимальный срок, автодаты, доступность и удаление тарифов,
обязательные поля, положительные периоды и платежи, пополнение, списание,
выручка по тарифам и клиентам, нехватка денег и полный откат, точный остаток,
повторное проведение, отмена и её идемпотентность, снятие проведения,
границы дат, работа задания и неизменность купленных условий.
Отдельный тест одновременно проводит две подписки, на которые суммарно
не хватает денег, и проверяет отсутствие перерасхода.

Отчёт JUnit: `build/reports/tests/test/index.html`.
Покрытие JaCoCo: `build/reports/jacoco/test/html/index.html`.
В `gradle.properties` включена совместимая кодировка аргументов JVM, чтобы
Gradle-тесты работали на Windows даже в папке с русским названием.

Дополнительная HTTP-проверка **уже запущенного** приложения:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/smoke.ps1
```

Она входит через API с CSRF-защитой, проверяет формы и меню, создаёт отдельного
тестового клиента, два тарифа, платёж и подписку, проверяет проведение,
нехватку денег, остатки и выручку, затем отменяет подписку.
Созданные тестовые записи остаются в выбранной базе. Для полностью временной
проверки запускайте отдельный экземпляр с базой в памяти:

```powershell
java -jar build/libs/onno-subscriptions-1.0.0.jar --server.port=8081 '--spring.datasource.url=jdbc:h2:mem:smoke;DB_CLOSE_DELAY=-1'
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/smoke.ps1 -BaseUrl http://localhost:8081
```

## Структура

```text
src/main/java/ru/onno/subscriptions/
  model/       справочники, перечисления, документы, строки и регистры
  repository/  типизированные репозитории onno
  service/     мост lifecycle, регламентное задание, отмена подписки
  ui/          EntityView, Layout, Page и ActionSpec
src/main/resources/application.yaml
src/test/      интеграционные тесты и конфигурация базы в памяти
scripts/       HTTP-проверка
.github/workflows/check.yml
```

## Соответствие заданию

| Требование | Реализация |
| --- | --- |
| Сущности, перечисления, документы и табличная часть | `model/` |
| EntityView, форматы, подсказки, порядок и ширина полей | `ui/*View.java` |
| Боковое меню | `MainLayout` |
| Остатки и выручка | `PersonalAccount`, `TariffRevenue` |
| Проведение и недостаток денег | `Payment`, `Subscription`, транзакции onno |
| Validated + BusinessRule | клиент, тариф, платёж, подписка |
| Подстановка дат, цен и расчёты | lifecycle документов |
| ScheduledJob + BackgroundTask | `SubscriptionStatusJob` |
| Тесты | `SubscriptionIntegrationTest`, HTTP smoke |
| README запуска и использования | этот файл |
| Бонусный дашборд | `DashboardPage` |
| Бонусная отмена с причиной | `SubscriptionView`, `SubscriptionCancellation` |

Подготовлены конфигурации systemd и nginx и [инструкция для VPS](docs/vps.md).
Для бесплатной публичной демонстрации подготовлены Dockerfile, render.yaml
и [инструкция Render](docs/render.md). На бесплатном Render база временная
и теряется при перезапусках и засыпании. Для постоянной базы подготовлен
[профиль PostgreSQL и инструкция Neon](docs/postgres.md); подключение
требует создания базы и задания переменных на Render.
Фактическое развёртывание на сервере пока не выполнено.
Отдельная система трассировки не включена.

## Публикация для сдачи

Создайте публичный репозиторий GitHub и отправьте туда исходники проекта.
`.gitignore` исключает базы, кэши, логи, сборку и скачанный справочный репозиторий.
Секретов в исходниках нет; `admin/admin` — локальная конфигурация для проверки.
GitHub Actions автоматически запускает тесты и собирает JAR на Java 21.
После успешной проверки отправьте проверяющему ссылку на репозиторий.

Документация фреймворка: [onno](https://github.com/onno-erp/onno-framework),
[API и руководства](https://docs.onno.su/).
Проверенные особенности опубликованного API описаны в
[framework-notes.md](docs/framework-notes.md).
