# Проверенные особенности onno 3.4.1

## Отображение карточек в окне 768–1023 пикселя

Пользователь воспроизвёл `React.Children.only expected to receive a single React
element child` при открытии сохранённого клиента и подписки во встроенном браузере
VS Code. Стек опубликованного `index-CFVh44-u.js` указывает на Radix Select.
В `components/ui/facet-sheet.tsx` ширина 768–1023 CSS-пикселя выбирает режим
`modal`. В `components/ui/select.tsx` эта ветка передаёт два дочерних элемента
(фон-кнопку и Content) в SelectPrimitive.Portal; Radix Portal использует asChild,
которому нужен один элемент. Это объясняет ошибку на этапе отображения формы.

Обход для ручной проверки: обычный браузер, ширина страницы больше 1023
CSS-пикселей, развёрнутое окно и масштаб 100%. Этот режим использует другую
ветку SelectContent. Обход требует подтверждения в пользовательском браузере;
визуальная автоматическая проверка недоступна в текущей сессии.
Исходники и опубликованный bundle фреймворка не изменены.

## Ошибка HTTP при недостатке денег

Минимальное воспроизведение: `PersonalAccounts` типа `BALANCE` с
`allowNegative = false`, проведённый приход 400 ₽, документ расхода 900 ₽,
запрос `POST /api/documents/Subscriptions/{id}/post`.

`PostingEngine.checkNonNegativeBalances` выбрасывает `IllegalStateException`.
Транзакция откатывается правильно: остаток, выручка и признак проведения
сохраняют прежние значения. В опубликованном UI starter исключение не
преобразуется в бизнес-ошибку HTTP, поэтому стандартный ответ — 500.

Приложение адаптирует только этот конкретный отказ своего регистра
в `PostingErrorAdvice`: HTTP 409, `error = insufficient_funds` и сообщение
«Недостаточно средств на лицевом счёте…». Защиту денег продолжает выполнять
транзакционный механизм onno. Другие `IllegalStateException` не маскируются.
Исходники фреймворка не изменены. Это описание можно использовать для issue
в upstream; публичный issue автоматически не создавался.

## Дата на новой форме

`GET /api/divkit/documents/Subscriptions/new` возвращает значения атрибутов
из нового объекта, включая дату начала. Системное поле `date` в initial
не включается. При создании документа через API дата автоматически
назначается write lifecycle; дата сохранённого документа заполнена.
Проверяется HTTP smoke. На пустой форме дата документа может быть пустой
до первого сохранения; её можно задать вручную.

## История отменённых движений

`getRecordsByDocument` включает неактивные движения. При отмене через
атомарный `repost` они остаются с `active = false`, но исключаются из
остатков и оборотов. Поэтому проверки отмены проверяют отсутствие
активных движений, а не физическое удаление строк истории.
