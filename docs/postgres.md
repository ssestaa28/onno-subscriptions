# Постоянная база на Neon

Для размещённого на Render приложения можно подключить внешний PostgreSQL.
Локальный запуск по умолчанию продолжает использовать H2.

1. Создайте проект Neon на тарифе Free. Выберите регион рядом с Render.
2. В Connect выберите прямое подключение (Connection pooling выключен).
3. В Render → Environment добавьте четыре переменные:

| Переменная | Значение |
| --- | --- |
| SPRING_PROFILES_ACTIVE | postgres |
| DB_URL | jdbc:postgresql://HOST/neondb?sslmode=require |
| DB_USERNAME | пользователь из Neon, обычно neondb_owner |
| DB_PASSWORD | пароль пользователя базы из Neon |

HOST и имя базы возьмите из Connect. Если имя базы отличается от neondb,
замените его в DB_URL. Это JDBC URL без пароля; обычную строку
postgresql://user:password@host/database нельзя вставлять в DB_URL.
Пароль задавайте только в Environment, не в GitHub и не в скриншотах.

4. Сохраните все переменные вместе и перезапустите сервис.
5. Дождитесь Live. onno создаст схему в новой базе автоматически.
6. Заполните демонстрацию заново: записи из прежней H2 автоматически
   не мигрируют. Проверьте остатки, затем перезапустите Render и убедитесь,
   что те же записи и остатки сохранились.

Данные PostgreSQL хранятся отдельно от контейнера Render. Засыпание сайта
и новое развёртывание не удаляют эту базу. Бесплатный Neon имеет лимиты
вычислений и хранения; это не обещание неограниченной работы.
JobRunr и регламентные задачи используют ту же базу и создают запросы,
поэтому расходуют вычислительную квоту, пока приложение работает.

Подготовленный профиль не проверен на конкретной базе Neon до её создания
и подключения. Секреты подключения в репозиторий не включены.

Документация: https://neon.com/docs/get-started/connect-neon
