# Бесплатная демонстрация на Render

Это публичная демонстрация с временной H2-базой. Free Web Service засыпает
после 15 минут без входящего трафика; следующее открытие требует холодного
старта. Файлы базы теряются при перезапуске, повторном развёртывании и
засыпании сервиса. Локальная база остаётся на вашем компьютере.
Для постоянных данных нужна отдельная внешняя БД; она в эту конфигурацию
не входит. Render не является VPS из дополнительного пункта задания.

## Публикация

1. Загрузите исходники в публичный репозиторий GitHub. Dockerfile,
   render.yaml и deploy/render-start.sh должны быть в репозитории.
2. В Render выберите New → Blueprint, подключите репозиторий и проверьте,
   что выбран план Free. Примените конфигурацию render.yaml.
3. Дождитесь Live. Render сам собирает Java 21 приложение через Docker.
   Устанавливать Docker локально не требуется.
4. По просьбе автора демонстрации Blueprint задаёт APP_ADMIN_PASSWORD=admin.
   Это публичный демонстрационный доступ: любой посетитель может менять записи.
   Для реальных данных замените пароль в Environment.
5. Откройте адрес сервиса с окончанием /ui/. Пользователь admin,
   пароль admin. Создайте демонстрационные данные
   через интерфейс, как описано в README.

Альтернатива Blueprint: New → Web Service → репозиторий → язык Docker →
план Free. Добавьте APP_ADMIN_PASSWORD со своим уникальным паролем
в Environment перед запуском. render.yaml применяется только через Blueprint.

Контейнер слушает PORT, заданный Render, на 0.0.0.0. Запускается от отдельного
пользователя. Java использует не больше 256 МБ heap; остальная память нужна
для JVM и нативных структур. Отсутствие пароля останавливает запуск.

Проверка через API и заполнение демонстрации из локального PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/smoke.ps1 -BaseUrl https://onno-subscriptions.onrender.com -Password admin -DemoData
```

Сценарий проверяет проведение, недостаток средств и отмену, затем оставляет
новую проведённую подписку на 1100 ₽ с остатком 400 ₽, отменённую подписку
и черновик после отказа. Каждый запуск создаёт нового клиента и два тарифа.

При ошибке откройте Logs сервиса. Конфигурация подготовлена локально;
сборку Docker-образа и работу в среде Render нужно подтвердить первым deploy.
